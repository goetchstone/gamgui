# Incident

**One line:** the incident screens, Incidents, Investigate, Respond and Report, work a compromised account from first report to the review: pull and read the logs, see where each account stands, lock it and undo what the attacker left from one preview with the person's address typed, see who their emails reached, and export a report with the evidence. Ported from SwiftGamGui, whose `docs/domains/compromised-account.md` holds GAM's behaviour for each command and the history behind each rule. Treat that runbook's list of past fixes as a checklist when changing a slice.

**Owns invariants:** #1 (a delegate or send-as address is one plain address, a list of IDs is `id_list`'s), #2 (one held preview, read fresh before the first write).

## Files
- `core/incident/check.py`: the reads in words and `findings`. Pure.
- `core/incident/reads.py`: `read_check`, the reads at once, each failure said beside its list.
- `core/incident/secure.py`: `steps`, in run order, as offboarding's `OffboardStep`, run by `lifecycle.run_offboard`.
- `web/routes/incident.py`; `incident.html`, `_incident_check.html`, `_incident_confirm.html`, `_incident_run.html`.
- `tests/test_incident_check.py`; the mock's `print forward`, `print sendas`, `delete sendas`, `print admins`, the drafts' listing and `delete messages ids`. carol@ is the taken-over account.

## What to know
- **A read that failed is said beside its list, never "none"**: `Read.problem`. Only the account's own read stops the check, since an alias reads as its owner and every other read needs the primary address.
- **Nothing to undo is ticked to start.** The lock is on, except clearing recovery, which is a loss when the values are the person's own.
- **Every step but the picks is a switch.** While the reset runs every other step `requires` it. Otherwise nothing stops anything: a refused sign-out (the admin token's scope) mustn't stop forwarding off (the service account's).
- **What a preview holds runs**, bound to that check's `run`. A pick has to name what the check listed, whatever was posted, and the primary send-as address is never one.
- **Read fresh before the first write**: the same address, suspension and admin flags, not the admin GamGUI signs in as (`cut_off_refusal`), and each scheduled email held still scheduled. One Gmail sent since may be its Sent copy under the same ID, the only copy with the whole Bcc list, so a refused run drops the check: previewing it again would hold the same IDs.
- **The address is always typed** (`guard.enforce(typed_address=...)`), with `confirm` too from ten steps.
- **Scheduled emails go first after the reset**: Gmail sends one at its time with nobody signed in, the lock doesn't stop it, and it isn't a draft. Only one plainly labelled `SCHEDULED` by GAM's own count, and never `SENT`, is deleted as one.
- **Drafts are deleted, not trashed**: a draft in Trash may still be a draft, and sendable. Only the subject is read, since a phishing draft's Bcc runs to hundreds of addresses. The listing and the delete get ten minutes (`MESSAGES_TIMEOUT`).
- **"None" needs GAM's word.** GAM skips a refused token without a word and exits 0 (`handleOAuthTokenError`), so no rows can mean Gmail was never asked. A listing of drafts or scheduled emails is none only on exit 60. Gmail always lists the primary send-as address, so an empty send-as list is `Incomplete`, and then no filters, delegates or forwarding addresses isn't "none" either. An auto-reply read with no `Enabled:` line is unknown, never off.
- **A delete counts what GAM says it deleted.** GAM skips a batch on `serviceNotAvailable` without a word and exits 0, and a scheduled email in it still goes out, so a step short of the count fails.
- **"Already done" belongs to one person**: after a run, what finished is switched off in the next check of that person alone (`incident_done`, added to by each run, so a second run's check doesn't switch the reset back on). Those ticks once carried to the next person typed in SwiftGamGui, whose plan then skipped the reset and the sign-out.
- **The auto-reply's text is the attacker's**, as are subjects and filter words: autoescaped, and `Vacation.from_show_text` reads settings only above `Message:`.

## The logs
- **Each log is read whole, oldest first** (`pull.complete`). One read of the window first: most come back short of the cap. One at the cap is read a day at a time from the window's start, each day read back from its end until it's whole, an event read twice kept once. Bounded: 100 reads a day, 200 a log. Past either, a read that fails, or a day still at its cap, it stops at that day's start and says how far it read, with Read the Rest. The attack is the oldest part, and the newest is the easiest to read again.
- **The Chrome and admin logs' reads for accounts** are low volume and read newest first, both ways at once: Chrome by the profile's account and by GAM's device match, the admin log by what was done to the account and what it did. One read failing fails the log in GAM's words, never a part passed as the whole.
- **A window is fixed once, as times**, when the pull starts: GAM's `-72h` counts from each read and rounds to the minute, and a Gmail log queued behind others would drift past 30 days. Not for the Chrome and admin logs' reads for accounts, which use `-Nh` and `now`. Gmail reads at most 30 days, and the screen says so. Read the Rest on Gmail ends 30 days past where it stopped: moving the start up instead would skip the stretch between and claim the log whole (a fix SwiftGamGui still needs).
- **A row whose address wasn't asked counts toward each account asked**, for whether a read reached its cap: an old name, or no `actor.email`, could be any of theirs. Otherwise 999 + 1 read as whole at a cap of 1000. An extra read, never a missed one (also still to fix in SwiftGamGui).
- **A log stopped before anything of it stood isn't exported** as an empty file, and a part-read one is named `-partial`.
- **A pull by address reads the Devices log's registrations for the accounts asked**: that log records no address, so filtering would drop it whole.
- **One address that isn't a user fails the whole log in GAM**, so the route checks the accounts against the directory first.
- **Parsing runs off the event loop** (`asyncio.to_thread` in `GAMConnector.activity`), and a report's columns are worked out once, not per row (`_Columns`): a pull is up to hundreds of reads of a thousand events each.
- **A log that wasn't read is said, never an empty CSV** that would pass as no events. Export All's `about.txt` says the window, the accounts, the address and how far each log read.
- **Not kept on disk yet:** a pull is held in memory until a kept incident saves it (E4).

## The log reader
`core/incident/reader.py`, ported from SwiftGamGui's `Assist/LogReading.swift` with its tests. Code finds and code recommends; a draft only names a person or a Message-ID for a screen to open.
- **A suspect address is one Google called suspicious, or the one you pulled by**, never one only because many accounts used it. A person's own failed challenge is flagged too, and makes no suspect. Past ten accounts signing in from one, it's set aside as likely shared: securing everyone behind an office's address would lock the office out.
- **Google's mark isn't always the attacker**: a sign-in proved with a passkey is the person, unless the account added a passkey in these logs first, and a re-sign-in from an address they use unmarked is theirs.
- **Google's own warnings have no actor**: the account is `affected_email_address` (failure log 2026-10-22). Where there is an actor, that parameter names someone else.
- **Every Gmail event is `delivery`**, and `event_info.mail_event_type` says what happened. Only 1 and 35 are sends: the rest, from the attacker's address, are the person's own mail the attacker read, and pulling it would take real mail from everyone (failure log 2026-10-23).
- **A device action counts only once `EXECUTED`**: a guessed `SUCCESS` matched nothing Google sends, so a computer an admin blocked stayed on the list (failure log 2026-10-22).
- **The lock is read in time order**: a reset and a sign-out since the attacker's first event, by an admin not from a suspect address nor through an account the attacker held, or by Google. A suspension later undone isn't one. A sign-in from a suspect address after a lock starts it over.
- **Linear in the events**: each account's rules read only its own events and the admin's done to it (`_Accounts`), and Who it reached is two passes over the Gmail events. Run off the event loop, once a pull. 200,000 events read in under a second.
- **A difference from Swift:** Python compares strings by code point, so the two forms of an accented address count apart. A warning to one doesn't show the other warned, which over-warns, the safe side.

## Respond: where things stand, what's left, what's done
The incident screens are **Incidents**, **Investigate** and **Respond** (`_incident_nav.html`), with the open incident's title above them. One reading (`_current_reading`, cached by the pull and its context) draws both parts: `findings` on Investigate, `respond` on Respond. Nothing here changes the tenant, and each button opens a screen with its own read, preview and confirmation.
- **Done is the latest word, never older than the log.** A later Find showing a copy or left unsure takes back an earlier run or check, and a send, delivery or release the log shows after the last look puts the email back on the list. SwiftGamGui has neither: found by review here.
- **Done from the audit log** (`core/incident/runs.py`): an email's latest Phishing run ended trashed on every step it held, and Find had searched everywhere. A run's writes record `run` (its job ID), `domain`, `steps`, `searched_everywhere` and `by`. A record without them is passed over: never shown done, so never hidden. A failed or unfinished step, or a mailbox Find couldn't search, stays to do and says so.
- **Nobody here has it** (`NobodyHasChecks`, `nobody-has.json`): what each Find last showed, kept on this Mac since a read is never audited. Gone only with every mailbox and its Spam searched. If it can't be kept, Respond says so.
- **Marked done by hand** (`Record.ticks`, `Reading.ticking`, cheap, so a tick never reads the pull again): needs an incident open. Matched by kind, words and basis, so an item the logs later say more about is to do again. The route only takes an item on the list now of a kind that can take it (`Task.tickable`): never a lock, recovery details, a computer or a read, which the logs or this app show.
- **That was them** (`KnownSignIns`, `known-sign-ins.json`, true across incidents): that account's sign-ins from that address make no suspect. At most 500, each one account, one IP address and a note. Only a pair the reading offers can be marked. Listed with an Undo, never hidden.
- **Do It Here**: `/incident?person=…&fix=clear_recovery` picks only that fix, with the lock left off. The pick waits for its own check (`_pick_for`), fired from its own element, so the screen's form never carries it: a check by hand, another person's, or a run going on drops it. The screen says the rest of the lock is off. Computers come with the devices slice.
- **Show the events** (`pull.Filter`, in the page's address): the logs narrowed to what a to-do item is about, said in words, with Show all. Each log's CSV then saves just those events, named `-narrowed`; Export all is every event. A log that stopped short stays said, with none kept: no events there isn't none at all.
- **Pull again**: the logs that stopped short, for those accounts in the directory (20 at most, those left out named), over the window the first read looked at. With an incident open it's saved, with what was on screen if that wasn't, and everything saved is shown; otherwise it's put together with the pull shown, and a narrower read never takes away what the wider one found.
- **A narrow read never makes a log whole** (`merged`, `Log.covered`): a log that stopped short stays so, `-partial` in its export, until a read holds what it left out. A read of just some accounts covers those alone, which clears the to-do for them and leaves it for the rest. A read by an address covers nothing. SwiftGamGui clears the log on any whole read: a port that differs on purpose.
- **While a pull is saving and merging**, the reading and Export all wait: it has ended its reads and isn't yet what's shown.

## The report
`core/incident/report.py` (pure: `make`, `blocks`, `text_of`, `markdown_of`), `core/incident/report_pdf.py`, `web/routes/incident_report.py`. Made at most once for each change of what it's made of (`st.incident_report`): the reading and its context, the record, the audit log's size and time, the directory's 2-Step Verification, the saved reads.
- **What this report can't show** (`_coverage`, a section of its own above the numbers, in all three formats): the logs read, for whom and over what window; each log that wasn't read or stopped short; default logs not pulled; a group not read; a read not saved, or saved and unreadable; the audit log read back only so far; the directory's age. A report gets handed on without its screens, so it can't read complete when it isn't. Lists that can't be everyone carry `-partial` in their names.
- **Every number opens its list**, drawn to 300 rows, with a CSV of them all. 2-Step Verification is "on" only for an account found and enrolled, "off (suspended)" for a locked one, and blank when the directory isn't read or doesn't hold them. No bounce is a number of its own: if it bounced, they did not get it. **Steps taken** doesn't count a step that failed or a note, which are listed beside them.
- **What was done**: a long attack never pushes the response out, since the timeline keeps the earliest 200 and always what was done about it, and says how many it left out. What Google's logs show done to each account, what this app's audit log shows it ran to an account touched or a person here reached since the attack, emails pulled, each warning that counts, what was marked done by hand, and the notes, each beside what shows it.
- **One document, three formats**: `blocks` is drawn as text, Markdown and PDF, so they always say the same. Every piece of Markdown is escaped (`markdown_escape`): a subject an attacker wrote is its words, never a link, an image, HTML, a heading or a list. The PDF is a small writer with no dependency, using PDF's own Helvetica and Courier, so it's the same anywhere. Those fonts hold Western text only: a character they can't show reads "?", and the PDF says so, the Markdown and text having it.
- **Export report** is made first (`POST /incident/report/export`), then saved from a one-use link: a download link's response is saved as a file in the app window whatever its status, so a failure has to be said on the screen. Built in a `0600` temp file, removed once sent, and any left stranded is swept at the next export. The report in three formats, `who-got-it.csv`, `who-it-reached.csv`, `emails.csv`, `accounts.csv`, `steps-taken.csv`, `still-to-do.csv`, `emails-pulled.csv`, `timeline.csv`, `evidence/` and `evidence-sha256.txt`. Evidence that can't be read stops it: a report never says more than it holds.
- **Left out of SwiftGamGui's**: the on-device model's draft of the summary, which is Apple-only. The summary is typed. The sign-off (Close Incident) isn't built in either app.

## Computers, phones, apps and scripts in Check Account
`core/person_reads.py`, `core/incident/check.py`, `core/incident/secure.py`. The check reads each on its own, so one failing says so beside its list and the rest stand.
- **Computers** (`print_devices`): each with its state. Only those still signed in count in the findings, and one blocked or wiped stays listed, said as such. Without the devices scope it says how to add it (`computer_note`), never "no computer".
- **Block it, or take the account off it** (`block_device_user`, `delete_device_user`, step key `computer`, after the send-as steps): radios on each computer, keep by default, in the same preview and run as the lock. The name is held to `devices/<id>/deviceUsers/<id>`: never `query:`, a list, or the API's `-` wildcard, which is every device. A name that fails leaves that computer unpickable, never the plan refused. The route only takes a computer the check listed as still signed in. **Exit 0 isn't done** (`device_user_done`): GAM builds the service first and exits 0 with no word if a refreshed token was refused, and exits 0 while Google's operation is still going, so each step reads GAM's own line for that name, or fails saying so. The computers read treats empty stdout the same way, since a real none prints its header. These write through Cloud Identity's devices API: the delegation needs the full scope, since `.readonly` reads but can't block.
- **Do It Here on a computer** (`pick_computer`): by the Devices log's `RESOURCE_ID` as Google's device ID, and one found that way but no longer signed in picks nothing. With no ID match, the nearest first signed in (`createTime`, never `firstSyncTime`, which Google moves) within two minutes of the registration, and the screen says it was matched by time. Only a computer's to-do item offers it: a phone's points at the Admin console. Nothing matching picks nothing, and the screen says so. It's the Do It Here rule: that fix alone, the lock off, said on the screen.
- **Phones** (`print_mobile_devices`) and **apps** (`print_user_tokens`, grouped by app) only list and say. The sign-out revokes the apps; wiping a phone is the Admin console's.
- **Apps Script projects** (`print_script_projects`): the person's own standalone projects, the bin's included. Exit 60 is `printFileList` printing no row, which overwrites a failure's own code, so it's "none" only with GAM's "Got 0 Drive Files/Folders … for <user>..." and no other line. Anything else is a failure. GAM has no Apps Script commands: a project's triggers aren't listed, and a script bound inside a Sheet or Doc only shows as a connected app.
- **Live checks owed, all on throwaway accounts**: blocking and removing a computer haven't run on a real tenant in either app. Whether the Devices log's `RESOURCE_ID` is Google's device ID is unknown (the match falls back to time), and so is what Google logs for a block done through the API.

## Who it reached, and where it started
The reader works both out (`Reach`, `WayIn`); `_incident_reach.html` and `_incident_wayin.html` draw them. Reads and this Mac only: nothing is sent. **Over-warning is safe, under-warning the harm**: only an address that bounced and isn't a person's mailbox here is left out, and a warning counts only on the log's own word.
- **Pick the warning** (`Record.warnings`, bare Message-IDs): only a candidate the reading offers for that email can be picked. It's checked again at every reading: the attacker's own, one from before, or one not in the logs read doesn't count, and says why. With none counting, warned is unknown, never "no".
- **Groups** (`core/incident/groups.py`): a group it went to (inside, no one's mailbox, not reached through another group, not bounced from) is read for its members in the background, then the groups in those, each once. At most 20 a call. A failed read, no group at that address, one listing no one, and past the limit are said under the email and count on the warning's send: members are read as they are now, so empty isn't "nobody got it". Opening Respond again retries them, nested ones too, and what's said stays until each answers. A member with no address is said, never dropped unsaid. GAM's CUSTOMER member means everyone in the directory. The screen polls a small status while they're read, and refreshes the reading once at the end.
- **Whose Gmail log the pull holds** (`Log.whole`, `Context.gmail_whole`): worked out from a read's rows, never a window it claims. A read with no address filter holds every event of its accounts from its oldest event to its newest, or to where it read through. None for a read by an address, a newest-first read to a cap (Chrome's and the admin log's for accounts), or a saved read whose `about.txt` doesn't say whose and from where. It's what tells a quiet mailbox from one not read.
- **Who's a person** (`_people_of`): their aliases and the domain aliases Google adds (`nonEditableAliases`, which GAM returns with the aliases asked for), read as them. A person's own address is never taken by another's alias.
- **`reach.csv`** says which email, and carries `-partial` in its name when it can't be everyone: a send naming no one, an address that doesn't read, a group not read, the Gmail log short.
- **That's the phish** (`Record.phish`): only an email the logs list as a way in, and only the operator says which. Code lists emails from outside in the 3 days before the first attacker sign; nothing guesses.

## A kept incident
`core/incident/store.py`, `web/routes/incident_kept.py`. Each incident is a folder under `app_data_dir()/incidents`, named by its ID (the day it was opened plus six hex digits): `incident.json` holds what only a person can say, and `evidence/` one folder per saved read, exactly as Export all writes one. Everything else is worked out from the evidence when shown.
- **Nothing here takes a path from a form**: an ID is checked, and a saved read's name is cleaned. An export comes in as a zip, and a member is only matched by its whole name against what this app writes, then read to a bound: no `../`, no zip bomb. Every file is opened relative to a held directory, `O_NOFOLLOW`, a regular file, `0600` in `0700` folders.
- **Whole or not at all, a crash included**: `incident.json` is written to a temp file and renamed; a saved read is written in a `.saving-` folder readers skip, and only then given its name (the next save clears what a crash left). An unreadable record is moved aside and named at every launch, never saved over. A store whose folder can't be read refuses, so nothing is made over what's there. An ID is never one kept already.
- **A saved read can come from someone else's zip, so reading one back never stops the others**: anything that fails names it as unreadable and the rest are shown, and only a read that reads back gives an address as swept. `about.txt` is parsed without a backtracking pattern (one froze the app for seconds on a few KB), and a time outside 1990 to 2200 isn't a time, since year 1 or 9999 can't be moved to a time zone.
- **An incident opens only while connected to its domain**, and an export that doesn't read back, or whose events have an actor and none here, is refused: one tenant's logs never go into another's incident. That's for an honest mix-up: a hostile file can write a row at the right domain, or `about.txt` lines that say an address was swept.
- **A pull is saved to the incident open when it started**, whichever is open when it ends. New, open, close and an added export refuse while one runs, and one that finishes after a pull or a connection change started doesn't open over them.
- **A pull made while it's open is saved before it ends**, and added to what's shown in memory, from the very text written. No saved pull is read again: in SwiftGamGui each pull re-read every saved one, and took minutes (its failure log 2026-10-23). What's shown from the evidence is never saved again. A new incident takes the pull just made.
- **Reading back** is the export's own format, not GAM's: no backslash escape, the `'` before a formula's lead taken off, `via` split back, and the parameters split on " | ", a piece that isn't `name: value` joined back to the value before it (a subject can hold " | "). Not kept by the export, so not read back: Google's unique qualifier. **Put together**: an event in two exports once, a log stopped at its cap only while every read of it was.
- **Bounded**: 200 incidents, 500 notes each, 100 saved reads each, 256 MB a file, 1 GB an export, 1 MB an `about.txt` and 3 million events a saved read (a zip of a few MB can unpack to that many rows, about 310 bytes each held).
- **The open incident's ID**, never its contents, is remembered in a file beside them, so it opens again after a restart.

## The shape the reviews kept finding
Each slice went through an adversarial review, and each found the same harm: **something reads finished, whole or proven when it isn't.** Look for it first when changing anything here: a read that failed or stopped short reading as none; a narrow read standing in for a wide one; a pick or a form applying to the wrong person or incident; a stale reading; a file with the name of the whole thing. GAM exiting 0 isn't its word that it did it.
