# Domain: Catalog & Builder

**One line:** Turns GAM's vendored grammar into a browsable, categorized command catalog and decides which commands become *runnable* (buildable) — 35 hand-curated writes/reads plus every confidently read-only command auto-promoted to a generic, injection-safe builder — powering the `/builder` screen.

**Owns invariant(s):** #3 (only confidently `READ_ONLY` commands auto-promote to runnable; the buildable-vs-browse boundary). Touches #1 (argv-only) and #8 (no `| tojson` in attrs) at the Builder route/template edge.
**Enforcement home:** `tests/test_builder.py` (`test_only_read_commands_became_generically_buildable`, `test_every_read_command_is_buildable`, `test_generic_read_argv_is_injection_safe`, `test_sensitive_reads_are_flagged_and_still_buildable` + the sensitive/export audit tests), `tests/test_catalog.py` (parse/risk/areas), `tests/test_command_contract.py::test_catalog_matches_grammar` (committed-JSON drift), `tests/test_polish.py::test_docs_state_the_real_catalog_counts` (the total/runnable/curated/promoted counts CLAUDE.md, README and ROADMAP state). Skill: `.claude/skills/add-builder-command`.

## Files
- `gamgui/core/catalog/parser.py` — shallow grammar parse: `parse_grammar()` → browse-only `CatalogCommand`s; category from `# ` headers, `_verb_risk`/`_find_verb` infer risk from the FIRST known verb (sets `uncertain=True` when no verb is recognized).
- `gamgui/core/catalog/readbuilder.py` — generic read builder: `parse_read_template()` (grammar line → slots + argv template) and `make_build()` (template → injection-safe `build(values)→argv` closure). Emits no verb of its own.
- `gamgui/core/catalog/catalog.py` — `load_catalog()`, the `_curated()` overlay (the 35 runnable writes/reads), `_make_reads_buildable()` (the auto-promotion gate), area grouping (`_AREA`, `AREA_ORDER`, `_area_of`).
- `gamgui/core/catalog/models.py` — `CatalogCommand`, `CommandSlot`, `SlotKind`, `Catalog` (sorting/search/`supports_export`).
- `gamgui/core/catalog/describe.py` / `nouns.py` — deterministic fallback `gloss()` when a command has no vendored description.
- `gamgui/web/routes/builder.py` — the `/builder` screen: browse/search, slot assembly (`_assemble`), preview, run, sequence, a read's result table (`/results`) and CSV export, `/pick` type-ahead.
- `gamgui/web/templates/_records_table.html` — a read's result: the filter form, `_records_meta.html` (the "N of M rows" count and the CSV link) and `_records_page.html` (one page of matching rows and the pager). A cell shows `server.cell(value)` (a list joined, a name dict as the name, another dict as `key: value · …`, never Python's repr), on one line (`truncate whitespace-nowrap max-w-[24rem]`, never `break-all`, which split addresses mid-word), whole in its `title`; `builder.js` expands a cut-off cell on a click with the table's `data-expanded` classes. The CSV export keeps raw values. The screen has no footer and puts its title in the search row, so the working pane gets the height (`h-[calc(100vh-9.5rem)]`); **Hide list** (`#list-toggle`, `aria-expanded`) hides `#catalog-col` and swaps `#builder-grid` to its `data-collapsed-cols`, remembered in `localStorage` (`gamgui.builder.list`, a per-viewer convenience; the page works without it).
- `scripts/build_command_catalog.py` — regenerates the committed browse-only `command_catalog.json` from `GamCommands.txt` on each GAM bump (buildable overlay is NOT here — it lives in `catalog.py`).
- `docs/builder-commands.md` — the fuller domain reference (it points at CLAUDE.md for the counts rather than keeping its own copy).

## How it works
`load_catalog()` = `_curated()` (35 hand-modeled commands with friendly slots + a `build` lambda calling a `GAMCommands` static method) **+** `_load_shallow()` (parse of the committed JSON, else a live parse of `GamCommands.txt`). Then `_make_reads_buildable()` attaches the generic `readbuilder` to every remaining command that is `RiskLevel.READ_ONLY` and not `uncertain`, flipping `buildable=True`. The route never shell-splices: `_assemble()` reads form slots and calls `cmd.build(slots)` to get an argv list; a read runs via `conn.catalog_read(cmd, argv)` (refuses a non-`READ_ONLY` command), a read's table exported to a Sheet is its own curated write (below), a mutation runs **only from its preview**: `/preview` holds the argv it shows under a single-use token (`AppState.previews`, flow `builder`; `_form_key` = the command id + its slot values) that the Run button posts back, and `/run` takes it — another command loaded or a slot retyped since, or a used, expired or missing token, answers with a fresh preview of what the form holds now (and the reason), never a run (a stale Run panel once deleted an account nobody had previewed, failure-log 2026-09-23). The held argv then goes through `guard.enforce(..., confirm_step=True)` (the preview's Run posts `confirmed=1`). There is no curated account delete (roadmap 2.9): Users → a person → Delete account refuses a Vault hold or an owned secondary calendar and reads both again at the confirm, which a Builder delete would walk around. `guard.enforce`'s typed-address rule and `_transfers` still apply to any delete argv a preview holds → `conn.apply` → `_run_write` (the chokepoint, invariant #2), audited as `apply` with the catalog id in `extra.command` (the preview's `meta["cid"]`; a sequence step's too) — it once recorded bare `apply`, and only the argv said which command it was. The sequence is held the same way (flow `builder_sequence`, keyed by its steps): a step added, removed or moved after Preview is refused. A running sequence has a **Stop** (its panel's and the jobs tray's, plan U5): `_run_sequence` checks it between steps, so the step in flight finishes and the panel says "Sequence stopped — … Stopped by you — N not attempted.". Reads carry no token — they change nothing and run from the live form. A tabular read's rows are kept whole in `AppState.builder_last_result` (with an `id`) and the table shows ten at a time: its filter box, **External only** toggle (a row naming "anyone" or an address outside the connected domain) and pager all ask `GET /builder/results`, which filters every row server-side and answers a page of the matches, with the "N of M rows" count and the CSV link swapped out of band (the count speaks through base.html's live region, `data-announce`). The download (`/builder/export.csv`) takes the same `q`/`external`, so it is the filtered set when a filter is on; a request naming an `id` that a newer run replaced is refused, not served the newer rows. The table and the CSV show every column any row has (ragged JSON). "List a shared drive's files" (`build.shared_drive_files`, roadmap 4.7) is a curated *read*: `user <member> print filelist select shareddriveid <id> showownedby any`, because GAM keeps only the person's own files by default and a shared drive's are owned by no one; it takes no admin access, so the person must be a member, and Google's refusal otherwise reaches the screen. A folder of mixed ownership into a shared drive (roadmap 4.8) is two curated writes queued in a sequence: `build.move_folder_to_shared_drive` (DESTRUCTIVE: no dry run, no undo) runs `user <owner> move drivefile id:<folder> teamdriveparentid <drive> retainsourcefolders duplicatefolders merge duplicatefiles skip`, and `build.copy_rest_of_folder_to_shared_drive` (LOW) runs `user <owner> copy drivefile id:<folder> teamdriveparentid <drive> recursive copysubfilesownedby others duplicatefolders merge duplicatefiles skip excludetrashed suppressnotselectedmessages` (the copy lists children trashed or not and would bring a trashed file back live; each of the person's own files left behind would otherwise be a NOT_SELECTED warning, exit 51). The folder goes as `id:<ID>`, so a DriveFileEntity keyword (`mydrive`, `ownedby_me`) can't stand for a whole Drive, and `root`, `rootid` (GAM's cleanFileIDsList, even after `id:`) and `appDataFolder` are refused. `duplicatefiles skip` because GAM's default, overwriteolder, deletes the same-named file in the drive. Both previews (single and sequence) run `_folder_moves`: the connector's `folder_count` (`print filelist select id:<folder> showparent showownedby any excludetrashed fields id,name,mimeType,owners formatjson`: printFileList exits 60 for an empty folder and for one it couldn't find alike, since its "no row" 60 overwrites the failure's 50, so the folder's own row (`showparent`) is what says it was read; 60, no folder row or a file without an owner is Incomplete) split by `shared_drives.count_folder` into the owner's, the domain's and outside files, and `drive_members` for `manages_directly`: GAM's verifyorganizer asks for the person's own permission, so a Manager only through a group is refused, and the preview refuses when the read says they aren't one (a read that failed is said, not a refusal). A move that left files behind exits 50 (a refused file update: owned outside the domain, or by someone who isn't a member of the drive, fileOwnerNotMemberOfTeamDrive) or 51 (a trashed child, NOT_MOVABLE_IN_TRASH; the move has no excludetrashed), last-wins, so in a sequence that step reads as failed and the copy still runs. The mock's folders are `tests/fixtures/drive_folders.tsv`; under `GAM_MOCK_STATE` it keeps `folder_moved.tsv` and `folder_copied.tsv`, refuses those files as Drive does, and answers a repeated copy with 51 (duplicate skipped). A sequence's preview offers **Export as a gam batch file** (roadmap 5.3, `GET /builder/sequence/export.txt?preview=<token>`, a `download` link, shown only on an unblocked preview): it writes the steps that preview holds (`previews.peek`, which leaves the Run's token unspent), never what is queued now, so a step added after Preview isn't in it (review finding); an expired or spent token, or an audit record that can't be written, is a 409 in fixed words. `core/sequence_export.batch_file` writes each step as `gam` plus its argv, every element `shlex.quote`d (GAM 7.52.05's doBatch reads lines, skips `#`, and `shlex.split`s each), a `# n. label` comment above it and `commit-batch` between steps, since `gam batch` runs its lines in parallel processes. A value with `\n`, `\r` or NUL is refused (it would end the line), as is a `password` followed by anything but GAM's own `random`, `uniquerandom` or `blocklogin`. No `set`/`datetime` line is written, so `%word%` in a value stays literal. The export records `sequence_export` (no connector, no export); the file runs outside the guard, and the preview says so. `tests/fixtures/sequence_export.txt` is the bytes SwiftGamGui must match; `tests/test_sequence_export.py` holds the quoting to a copy of doBatch's read loop. Not CSV: `gam csv` is one command template per row. The closed list of writes (roadmap 5.1, D4) is five curated commands, each one value one object as GAM 7.52.05's source reads it: `build.rename_user` (DESTRUCTIVE) `update user <u> primaryemail <new> noactionifalias` (users.update takes an alias as its key and renames the owner, so noactionifalias reads the account first: an alias is "Not Performed", 51; a taken address is 50, not 57; `vfe@` is refused, since GAM makes up a `vfe.<user>.<NNNNN>` address for it; `cut_off_account` counts a new primary address, so the connected admin is refused and an unknown account stops before GAM); `build.delete_group` (DESTRUCTIVE) `delete group <g> noactionifalias` (Google deletes the group behind an alias; GAM splits a list on commas and spaces and reads `csv`/`file` as a list's source, so the group is one full address); `build.create_admin` (DESTRUCTIVE) `create admin <u> <role> customer|org_unit <ou>` (the role by its name as roles.list gives it, `_HELP_DESK_ADMIN_ROLE`, matched without case, an unknown one a usage error; `id:`/`uid:` refused, since GAM sends what follows as an unchecked role ID; a blank org unit is the whole organization, `/` and `root` refused); `build.create_shared_drive` (LOW) `user <u> create shareddrive <name>` (created as that person, its only Manager; no restrictions, theme or org unit, each a second call after a sleep that can fail once the drive exists; Drive allows two drives with one name); `build.rename_shared_drive` (LOW) `update shareddrive shareddriveid <id> name <name>` as the admin (the explicit `shareddriveid` because a bare `name` or `shareddrive` would make the next word a drive name, matched without case). `connector.apply` passes each a `builder_done` check: exit 0 without GAM's own line ("Admin Role Assignment: <id>", "Shared Drive ID: <id>", "Group: <g>,", "User: <u>,") is "may not have happened", since `create admin` exits 0 with no word on Google's internalError; the Builder's success shows that line, so the new drive's ID and the assignment's ID reach the screen. Tests: `tests/test_closed_list_writes.py`. The counts are stated in CLAUDE.md #3, the README and ROADMAP — and only there: `test_docs_state_the_real_catalog_counts` fails if one drifts, and `scripts/bump_gam.py` rewrites all three on a GAM bump.

## Invariants & the failure history
- **The auto-promotion gate is the whole safety story (#3).** `_make_reads_buildable` skips `c.risk != READ_ONLY` and `c.uncertain`, and the generic builder emits *no verb* — so a promoted command can only ever read; a mis-classified `LOW`/`DESTRUCTIVE` line can never gain a run path. Guarded by `test_only_read_commands_became_generically_buildable`.
- **Risk comes from the first recognized verb, not token 2** (`_find_verb` scans `after[:6]`): `gam <UserTypeEntity> delete delegate` is DESTRUCTIVE, `gam update group … remove member` is LOW. An unknown verb → `uncertain=True`, risk `LOW`, never `READ_ONLY` → stays browse-only.
- **A read's export to a Google Sheet is a curated write, run only from its preview (plan F4).** Beside a table's
  Download CSV, **Export to a Google Sheet…** (shown when `cmd.supports_export`) posts the table's `id` to
  `/builder/sheet/preview`, which takes the read kept with that table (`builder_last_result["read"]`: catalog id, argv,
  target), runs the scope check (`conn.sheet_export_scopes()`, `check serviceaccount scopes <drive>,<spreadsheets>`, a
  read) and holds `(cid, read argv, Sheet name)` under a token (flow `builder_sheet`, keyed by the table's id, tenant
  captured first). It shows the exact `gam … todrive tdtitle "<domain> - <read>" tdnobrowser true tdnoemail true`, the
  admin whose Drive the Sheet goes in, that it is shared with nobody, and that it holds a **fresh read** (GAM reads
  again; rows can differ from the table, and a filter doesn't apply). A scope known to be missing offers no Export,
  with Setup's Domain-Wide Delegation link; one that couldn't be checked is said and Export still offered.
  `/builder/sheet/export` takes the token, `guard.enforce(..., confirm_step=True)`, then `conn.export_to_sheet` →
  `_run_write`. It takes the connector with the token, no await between them or from there to the export (plan F6):
  the token is bound to the domain its preview was made on, so GAM reads and uploads there, and the record names that
  domain even when a switch lands during the export; a switch before it drops the token like every held preview
  (`tests/test_domain_menu.py`, the three `sheet` tests). The result (`_export_result.html`, `core/sheet_export.outcome`) shows the link GAM printed, or whether a
  file was made (yes / no / unknown) and what to do. The Builder's Run no longer exports: its old one-click
  `td_export`/`td_user` fields put a Sheet in any user's Drive, and opened it in the Mac's browser (GAM's
  `webbrowser.open`). GATED in `tests/test_write_routes_guarded.py`; `tests/test_sheet_export.py`.
- **Two agent docs once claimed only the 26 curated commands run** (over 500 more do). That false claim made a reviewer flag correct `readbuilder` code as a violation — hence `test_docs_state_the_real_catalog_counts` now fails CI if the counts in CLAUDE.md, README or ROADMAP drift (README once said "~1,040", ROADMAP "533 of ~1,067", long after a bump).
- **Sensitive reads stay buildable and are audited (operator decision D3, plan S9).** `CatalogCommand.sensitive` flags two kinds in `catalog.py`. **Downloads, by rule:** every read whose verb is `DOWNLOAD_VERB` (`get`) — each `get` stanza in the grammar saves a local file (`targetfolder`, else GAM's `drive_dir`): `get drivefile`, `document`, `noteattachments`, `devicefile` (two forms), `photo`, `profilephoto`, `contactphotos` (two forms). **Secrets, by name:** `SECRET_READS`, `show`/`print backupcodes` and `show`/`print browsertokens`, matched on verb + object because the `raw.<line>` ids move on a GAM bump. `catalog_read` records `sensitive_read` (target, argv, `extra.command` = the catalog id, ok/error; never the output) and a `todrive` export of one is `sensitive_export`. `test_sensitive_reads_are_flagged_and_still_buildable` pins the thirteen syntax heads, so a bump that adds, renames or drops one fails (update SECURITY.md's list with it); `test_command_contract.py::test_the_download_verb_is_what_saves_a_local_file` pins the rule's premise against the grammar (every `get` stanza takes `targetfolder`; no other buildable read can emit a local-file option, since the read builder drops optional groups). A hand list once named only drivefile/document and missed the rest (review F4/F27). Not audited, by design: other content reads (`show`/`print messages`, `chatmessages`, `notes`). Every read run as a sequence step goes through `catalog_read` too (`_run_sequence` looks the step's `cid` up in the catalog), so it is `read` or `sensitive_read` with `origin` `sequence`, not `apply` (`test_a_sensitive_read_in_a_sequence_is_audited_as_one`, `test_a_plain_read_in_a_sequence_is_recorded_as_a_read`). Since F1 a plain read is recorded as `read` the same way (guard-audit runbook, "Read records"); its `rows` is what the table showed, counted by the same `parser.table_records` `_render_read` uses. The table's **Download CSV** of a sensitive result (`/builder/export.csv`) records `sensitive_csv_export` (target, argv, `extra.command`, `extra.rows` — the rows downloaded, the filtered set when the table's filter is on; never the rows themselves) through `GAMConnector.audit_sensitive_csv`, and is refused when there is no connector to audit through; a plain result's CSV writes nothing. Not covered: the `get` reads save the file wherever GAM's `drive_dir` default points (no `targetfolder` is passed).
- **The result filter covers every row (plan U1).** The table once rendered `records[:100]` and `builder.js` filtered those in the browser, so a sharing audit whose only external row was row 181 showed none. Filtering is server-side now, over the whole retained result; `tests/test_builder.py` (`test_the_filter_finds_a_match_past_the_first_hundred_rows`, `test_external_only_searches_every_row`, `test_the_csv_download_takes_the_filtered_set`) runs a 250-row result whose matches are past row 100. **External only knows the tenant's domains.** It once took any address not ending in `@<primary>` as external, so a secondary domain, a domain alias or a subdomain filled a sharing audit. `AppState.tenant_domains()` reads them with one `gam print domains formatjson` (`GAMCommands.print_domains`, `GAMConnector.list_domains`: every `domainName` and `domainAliasName` in the records) per connector — a tenant switch makes a new one — and only when the toggle is on; an address at one of them or a subdomain of one is internal (`_is_internal`). A failed read (the admin's grant may lack the domain scope) falls back to the primary alone and is tried again after `DOMAINS_RETRY` (10 min), not per keystroke. `test_external_only_counts_every_tenant_domain_as_internal` (the strict mock's example.com + alias.example.net + example.net) and `test_external_only_falls_back_to_the_primary_when_the_domain_read_fails`; the live tenant's `print domains` output is unseen — the parse reads the key names wherever they sit, JSON or flattened columns.
- **Curated `RiskLevel` is authoritative** (matches the connector's real `_run_write(... RiskLevel.X)`); auto reads inherit inferred risk, which is safe only because they can't mutate.
- **`transfer_data` offers `drive,calendar` as ONE argv element** (a `<DataTransferServiceList>`) to avoid the 409 from two overlapping same-user transfers, and appends the privacy level `all` whenever Drive is included (every file moves, private and shared, as offboarding's transfer does; GAM refuses a level for calendar alone). It is curated `DESTRUCTIVE`: handed-over ownership can't be taken back by a second transfer, so its preview asks for Confirm & run (and ten in a sequence, the typed word) — a bare POST once started one, while the README promised a confirmation (failure-log 2026-09-23).

## Gotchas / mock-lies traps
- **The mock lies here too.** `parse_read_template` builds argv from the *vendored grammar*, so a syntactically valid line can still be rejected live (e.g. some print/show commands reject `formatjson` — see MEMORY `gamgui-gam-formatjson`). `tests/fixtures/mock_gam.sh` proves the argv shape and table render, NOT that GAM accepts the command. Check `gamgui/resources/gam7/GamCommands.txt`, not memory.
- **An entry's continuation lines join its syntax; only its first line classifies it.** GAM wraps a long entry onto
  indented lines (691 of 1052 entries in 7.52.03); `parse_grammar` joins them into one `raw_syntax`, up to the first
  blank or unindented line (so a `<Thing> ::=` definition's body never attaches). The verb, risk, `uncertain` flag and
  name still come from the first line alone: a word on a continuation line (`version`'s `update`/`install`) never
  classifies an entry. Until 2026-11-15 the parser kept first lines only, so the syntax view was cut off and a promoted
  read couldn't emit a required token from a later line (`print chromesnvalidity`'s `cros_sn <SerialNumberEntity>`).
  The join changed no command's promotion; it changed 32 promoted reads' argv, each listed in that PR.
  `test_an_entrys_continuation_lines_join_its_syntax`, `test_a_continuation_line_never_classifies_an_entry`.
- **Optional `[...]` groups are dropped** — a promoted command runs on required args only. Exceptions kept as slots: self-contained `[<UserTypeEntity>]`/`[<CrOSTypeEntity>]` (emitted as `optpair` `user <x>`/`cros <x>`) and a top-level single-token optional positional whose placeholder names one value (`…Entity>`, `…Item>`, `…Name>`, `…ID>`: `info user [<UserItem>]`; not `[<PermissionMatchAction>]`, which is `pma process|skip`, nor a `[<Boolean>]` inside a flag group). A `<UserTypeEntity>` buried in `[data <…>]` is NOT touched.
- **Groups and repeats are not required arguments.** A required-looking `(...)` group is an alternation the builder
  can't choose (`(basic|allfields|…)`) or a repeat (`(addcsvdata <FieldName> <String>)*`), and `<X>*` may appear zero
  times: all are dropped, except `<A>|(…`, which keeps a slot for `<A>`. A `…Selection>` placeholder is a run of
  optional keyword groups and never becomes a slot. GAM's brackets don't always balance (`states <CourseStateList>])`),
  so the bracket and paren depths never go below zero: a stray closer must not make the groups after it required.
  `test_generic_read_template_from_a_joined_entry` pins each case; `test_no_promoted_read_emits_a_write_keyword` holds
  every promoted read's fixed words to the read side.
- **A slot value is never a write keyword.** GAM reads some slot positions as keywords (`print vaultcounts matter <M>
  <QueryItem>`, a bare `<ChatSpace>+`), so `make_build` refuses a value equal to `readbuilder.WRITE_KEYWORDS`
  (`todrive`, the local-file options, `update`, `install`), compared as GAM reads a keyword (`commands.as_keyword`:
  lowercased, every `_` dropped, as `getArgument` does), so `to_drive` and `target_folder` are refused too; the
  Builder shows the refusal. It once compared the raw lowercase only, and 348 promoted reads took `to_drive` (failure
  log 2026-11-21). `catalog_read` refuses any argv GAM would read as carrying `todrive` (`carries_todrive`) as a second
  line, and so do `export_to_sheet` (its read's own argv) and `audit_read`.
  `test_a_promoted_read_refuses_a_write_keyword_as_a_value`.
- **Search matches the whole entry**, so a word in an option deep in a continuation line finds the command too;
  `Catalog.search` puts the sections holding a *name* match first (`q=signature` still leads with "Set Gmail signature").
- **Sensitive-read heads** in `tests/test_builder.py` are the syntax up to the first `[` or `(` of the joined entry, so
  `get contactphotos` is pinned with its required `<PeopleResourceNameEntity>|<PeopleUserContactSelection>`.
- **Curated writes must exist in the pinned grammar** or `test_command_contract.py` fails; passing the contract proves *syntax exists*, not that the write does what you expect — verify destructive ones on a throwaway account (house rule).
- Directory data reaches templates via autoescaped `data-*` attributes read by JS (`el.dataset.*`), never `| tojson` in an attribute (#8).

## To do common tasks here
- **Add a runnable write** (or a friendlier read): follow `docs/builder-commands.md` §"Adding a buildable command" or run the `add-builder-command` skill — (1) verify syntax in `GamCommands.txt`; (2) add a `@staticmethod` to `core/gam/commands.py`; (3) arg-shape test in `tests/test_commands.py` (the grammar contract in `tests/test_command_contract.py` calls every builder by itself; a validated argument's values go in its `ENUM_ARGS`); (4) append a `_cmd(...)` to `_curated()` in `catalog.py` with the authoritative `RiskLevel`; (5) web test in `tests/test_builder.py`; (6) classify it in `tests/test_mock_gam.py` — a write needs a strict `mock_gam.sh` handler (the mock fails anything unhandled), a read with a new output shape a canned branch.
- **Change how reads auto-promote:** edit `parse_read_template`/`make_build` in `readbuilder.py`; re-run `test_builder.py` (esp. the injection-safety and boundary tests).
- **A read verb can carry a write keyword.** `version` is in `_READ`, and since GAM 7.52.00 its line takes
  `(update [quiet])`, which installs the latest GAM over the running one, unpinned. It stays safe only because the read
  builder drops optional groups; `test_runnable_gam_version_can_never_self_update` holds the runnable form to plain
  `gam version`. GAM 7.52.02 added `install <Path>` and `update path <Path>` on continuation lines, which now join the
  catalog's `raw_syntax`; `test_gam_version_still_offers_the_self_update_the_catalog_must_never_run` also reads the
  whole entry from the vendored grammar so the guard still has something to guard. On a bump, read the grammar diff
  for any new optional keyword that writes under a read verb; `test_no_promoted_read_emits_a_write_keyword` catches
  one that reaches a runnable argv.
- **After a GAM bump:** run `scripts/build_command_catalog.py` to regenerate `command_catalog.json`, then confirm `test_catalog_matches_grammar` and `test_docs_state_the_real_catalog_counts` pass (`bump_gam.py` rewrites the counts in CLAUDE.md, README and ROADMAP; by hand, update all three).
- **Re-group categories into areas:** edit `_AREA`/`AREA_ORDER` in `catalog.py`; `test_areas_group_the_categories` guards the shape.
