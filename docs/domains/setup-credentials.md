# Domain: Setup / Credentials Import

**One line:** Turns GAM's terminal-only authorization into a guided wizard — inspect a config dir, import `oauth2service.json` / `oauth2.txt` / `client_secrets.json` into the Keychain (with a fd-pinned, race-safe read), hand out the fresh-setup commands, and verify Domain-Wide Delegation.

**Owns invariant(s):** #5 (inode-based `(st_dev, st_ino)` import bound; directory pinned to a descriptor; each credential file opened `O_NOFOLLOW`). Also exercises #4 (secrets land only in the Keychain; staging plaintext is wiped).
**Enforcement home:** `tests/test_setup.py` (25 tests) + `tests/test_setup_web.py` (bounds/firmlink/NFD cases via the FastAPI route). No drift guard or CI hook beyond the offline pytest suite.

## Files
- `gamgui/core/setup.py` — the whole domain: `SetupService` + the module-level fd/identity helpers.
- `gamgui/web/routes/setup.py` — the screen: `GET /setup`, `POST /setup/import|fresh|verify|switch`; calls `candidate_dirs`, `import_dir`, `setup_commands`, `dwd_details`, `verify`. `verify` and `switch` share `_verify_and_activate`, the one place the connector changes.
- `gamgui/core/secrets/vault.py` — `FILENAMES` (logical name → GAM filename) and `_REQUIRED = ("oauth2service", "oauth2")`; `SecretsVault.set/get`.
- `gamgui/core/secrets/ephemeral.py` — `app_runtime_dir()`; `managed_setup_dir()` is its sibling `.../setup` (`0700`).
- `tests/test_setup.py`, `tests/test_setup_web.py` — see below.

## How it works
`SetupService.import_dir(path, domain)` is the spine. It calls `resolve_dir` (expand `~`, `resolve()`, then bounds-check the **resolved** path against `_allowed_root_ids()`, then require exists+is_dir), pins the directory with `_pin_bounded_dir` (open `O_DIRECTORY`, then `_fd_within_roots` walks up via `openat(fd, "..")` proving it sits inside an allowed root), reads each of the three `FILENAMES` with `_read_credential` (single component, `O_NOFOLLOW|O_NONBLOCK`, `fstat` regular-file check, then back to blocking and read from the *same* fd), `vault.set`s the bytes, and — only if the dir `_is_managed` (our staging dir, matched by inode) — wipes each imported plaintext file with `_wipe_file`. Bounds are computed by `allowed_roots()` = home (`_home_root`) plus a sane `$GAMCFGDIR` (`_root_is_sane`). `dwd_details(domain)` gives the DWD step everything up front: the client ID, `DWD_SCOPES` (every default-on service-account scope of the APIs GamGUI's curated `gam user …` commands call — Calendar, Gmail, Drive, Tasks — copied from the vendored GAM's `_SVCACCT_SCOPES` table, not guessed), the pre-filled Admin-console link (`dwd_auth_url`: the `clientScopeToAdd`/`clientIdToAdd`/`overwriteClientId`/`dn` shape GAM's own check prints) and whether the admin token (`oauth2.txt`'s `scopes`) holds `admin.directory.user.security` — offboarding's sign-out scope, which is a GAM *client-access* scope ("Directory API - User Security", picked in `gam oauth create`), so delegation cannot grant it and it is not in `DWD_SCOPES`. `static/setup.js` fills the domain from the admin email until the operator edits the domain field. `verify()` runs `GAMCommands.check_svcacct(admin, DWD_SCOPES)` — `check serviceaccount scopes <list>`, exactly the pre-filled scopes; a bare check asks about GAM's own larger default set and refused an operator who authorized only ours — and parses PASS/FAIL with `_parse_check`, surfacing a DWD auth URL via `_extract_auth_url` on failure. **Which tenant is active (plan U10b):** `AppState.create` starts on the first of `vault.list_domains()` (sorted); every page's header names the active domain and the admin its `oauth2.txt` names (`_tenant.html`, from the `active_tenant(request)` Jinja global in `server.py`; "Not connected" with no connector). With more than one domain in the Keychain, `/setup` shows a switcher; `POST /setup/switch` refuses a domain the index doesn't list, takes the admin from `oauth_admin_email` (else the one typed in "Your domain"), and runs the same verify — a read — so the connector changes only on a pass, the user/group caches are busted, and the header chip comes back out of band. Nothing is persisted: a relaunch starts on the first domain again.

## Invariants & the failure history
- **Bound by identity, not strings (#5).** `_within_roots` / `_reaches` / `_spellings` compare `(st_dev, st_ino)`, because `resolve()` doesn't fix case, NFC≠NFD bytes name the same dir, and `/Users` is an APFS *firmlink* — so `/System/Volumes/Data/...` is the same dir by a longer ancestor chain. `$GAMCFGDIR=/System` once put the real `/etc` back in reach via that firmlink chain; `_spellings` enumerates the volume spellings to catch it.
- **Pin first, prove second (TOCTOU).** A name-check-then-name-open race let a mid-request rename of the dir into a symlink read out-of-bounds bytes into the Keychain. `_pin_bounded_dir` opens the fd, *then* proves bounds from the fd; after the pin there is no name left to swap.
- **`O_NOFOLLOW` per file.** A credential file that is itself a symlink is not importable at all (even in-bounds) — closes the re-pointable indirection.
- **`O_NONBLOCK` per file, and the import off the event loop.** The `S_ISREG` check can only run after the open, and a plain open of a FIFO blocks until a writer appears — one `mkfifo`'d `oauth2service.json` froze the import, and since `POST /setup/import` ran the synchronous `import_dir` on the event loop, the whole app with it. `_open_in_dir` now opens `O_NONBLOCK` (a FIFO opens at once and is refused as not regular; `O_WRONLY` on one fails `ENXIO`) and restores blocking mode for the regular file; the route runs `import_dir` via `asyncio.to_thread`.
- **`_root_is_sane` on `$GAMCFGDIR` only.** Must be an existing *directory* (a file-as-root matched its own inode and a credential symlink imported its bytes) and must not be an ancestor of home or of `_SENSITIVE_DIRS` (`/etc /var /usr /System /Library /dev`). Home is trusted as-is on purpose: applying the rules to a launchd home of `/` emptied the root list and refused the app's own staging dir. Blank/unset `$GAMCFGDIR` must never become `/`.
- **Wipe only what you imported (#4).** `_wipe_file` re-`fstat`s the fd against the exact inode read, inside the pinned dir; swapping the staging dir for a symlink once made GamGUI zero/unlink another dir's files. `_is_managed` compares by inode (from `dir_fd` when pinned), not string — a case-variant spelling once skipped the wipe and stranded plaintext.
- **Fail-closed helpers.** `_fs_id` returns `None` on any stat failure; every helper treats `None`/errors as "no match" so a race or permission error can only *narrow* what's allowed.

## Gotchas / mock-lies traps
- The mock cannot touch this domain's core risk: it is all real-filesystem behavior (inodes, firmlinks, `O_NOFOLLOW`, TOCTOU), not GAM output. Tests use real `tmp_path` dirs and monkeypatched `HOME`, not `mock_gam.sh`.
- Case-sensitivity and `/private/etc/passwd` presence differ per machine — several tests `pytest.skip` on a case-sensitive volume or a missing `/etc/passwd`; a green run may have skipped the interesting case.
- `verify()` runs a **real** `gam check serviceaccount scopes …`. The strict mock answers as the vendored build's `checkServiceAccount` prints (`{scope:73} PASS (j/n)`, sorted, lowercased), refuses a non-service-account scope such as `admin.directory.user` as an invalid choice, and models a tenant that authorized exactly `DWD_SCOPES` — a bare check FAILs GAM's extra defaults and exits 1 (`SCOPES_NOT_AUTHORIZED_RC`). A `*partialdwd*` admin's tenant lacks `gmail.settings.sharing` and `tasks`, so verify's own check fails there too. On a failing scope GAM prints the table, `Some scopes FAILED or should be DISABLED!`, a gam-shortn link and the `admin.google.com/ac/owl/domainwidedelegation?clientScopeToAdd=<scopes checked + userinfo.email, sorted>&clientIdToAdd=…&overwriteClientId=true[&dn=…]&authuser=<admin>` link — **all on stdout** — and exits 1 (read from the vendored build's `checkServiceAccount`/`authorizeScopes` and `Msg.SCOPE_AUTHORIZATION_FAILED`; the mock prints the same). The runner raises `GAMError` on that exit, so `GAMError` carries the stdout, and `verify()` reads it as the check's answer (`_check_result(..., exited_ok=False)`: never ok, "N of M scopes" in the summary, the FAIL rows, GAM's link) only when the exit is `SCOPES_NOT_AUTHORIZED_RC` **and** stdout holds PASS/FAIL rows — exit 1 is also GAM's usage and action-failed code, which stay a plain error. A failing row that is not a scope — the system clock or the service-account key (a `*badkey*` admin in the mock: the key row FAILs and GAM stops before the scope table) — is named in the summary with what to do, and no delegation link is offered (it once read "Domain-Wide Delegation isn't authorized yet", failure-log 2026-09-25). `_extract_auth_url` prefers the direct `admin.google.com` link over the gam-shortn redirector. Against the mock it only proves parsing (`_parse_check`, `_extract_auth_url`), not that DWD is actually authorized. The `.app` launched from Finder has no `LSEnvironment`, so `$GAMCFGDIR` isn't seen unless launched from the exporting shell — `resolve_dir`'s error message says so; keep that caveat.

## Testing / live-verification status
`.venv/bin/python -m pytest -q tests/test_setup.py tests/test_setup_web.py` — fully offline (in-memory `InMemoryBackend` vault, no real GAM). Covers: fd-pin swap-after-check and swap-after-pin (`_after_the_bounds_check` / `_after_the_pin`), symlinked-credential rejection, a FIFO credential refused without blocking (core + route, via the `fifo` fixture's watchdog), the route running `import_dir` off the loop, wipe-never-destroys / wipe-only-imported-inodes, NFD + data-volume + case-variant home spellings, and overbroad-`$GAMCFGDIR` rejection for `/ /private /etc /System/Volumes/Data` etc. Verify asks for exactly `DWD_SCOPES` (`test_verify_checks_exactly_the_prefilled_scopes`; the mock's shape in `test_mock_check_serviceaccount_reports_the_scopes_asked_as_gam_does` and `test_mock_bare_check_serviceaccount_fails_on_gams_larger_default_set`). A failing scope is shown, not swallowed: `test_verify_shows_the_failed_scopes_and_gams_link_when_a_scope_fails`, `test_verify_a_non_check_failure_stays_a_plain_error`, `test_verify_with_a_failed_scope_shows_it_and_the_link_and_stays_disconnected` (the page, and no connector), the mock's shape in `test_mock_check_serviceaccount_fails_a_scope_the_tenant_did_not_authorize`. The DWD step's scope list and pre-filled link (`test_dwd_details_*`, `test_import_shows_the_scopes_and_the_prefilled_link_up_front`) and the domain inference (`test_setup_page_infers_the_domain_from_the_email`; a scratch Chrome run typed it, axe 0 on the rendered step). The tenant header and switcher: `test_header_names_the_active_tenant_*`, `test_one_domain_offers_no_switcher`, `test_two_domains_offer_a_switcher_and_switching_verifies_and_busts_the_caches`, `test_a_failed_switch_keeps_the_active_tenant`, `test_switch_refuses_*`, `test_switch_needs_an_admin_*`; a scratch Chrome run at 1100×760 switched tenants by the UI (header followed, no overflow, axe 0). **Not proven live:** an import from a real admin's `~/.gam`, the pre-filled link in a real Admin console, whether a real `oauth2.txt` records `scopes`, and a real `check serviceaccount` against a tenant — the import bytes and the DWD verify path have only ever run against fixtures.

**Confirmed live (2026-09-25, GAM 7.48.11, read-only):** `verify()`'s scoped `check serviceaccount scopes <DWD_SCOPES>` runs on a real tenant and `_parse_check` reads its real output (all seven scopes PASS, nine rows); `oauth2.txt` carries the connected admin under `decoded_id_token` and its granted scopes under a top-level `scopes` key, so `oauth_admin_email` and `dwd_details()['user_security']` read real values; `print domains` parses (the primary and Google's `.test-google-a.com` secondary). Still unseen live: GAM's output for a failing scope and for a rejected key — the mock's FAIL shapes are read from the vendored build, not captured.

## To do common tasks here
- **Add/rename a credential file:** edit `FILENAMES` in `secrets/vault.py` (and `_REQUIRED` if it gates readiness) — `import_dir`, `inspect`, and the wipe all iterate `FILENAMES`, no other change needed.
- **Widen/narrow where imports may live:** edit `allowed_roots()` and `_root_is_sane()`; add a matching bounds case to `test_setup_web.py`. Do **not** rewrite the identity checks as string comparisons (invariant #5).
- **Change the DWD scopes shown:** `DWD_SCOPES` in `setup.py`, from the vendored GAM's service-account table only (its `glapi` module; a client-access scope doesn't belong there); `test_dwd_scopes_are_service_account_scopes_only` is the tripwire. The list covers the curated commands: a Builder read of another API (Chat, Classroom…) may still fail verify, and GAM's own link then covers the rest.
- **Change verify parsing / auth-URL detection:** `_parse_check`, `_STATUS_RE`, `_AUTH_URL_RE`, `_extract_auth_url` in `setup.py`; assert in `test_parse_check_*` / `test_extract_auth_url`.
- **Change the fresh-setup commands shown:** `setup_commands()` (keep GAM7 order: `create project <admin>`, `oauth create`, `create svcacct`); guarded by `test_setup_commands_shape`.
- **Change how the active tenant is chosen or shown:** `_verify_and_activate` in `routes/setup.py` (the only place `st.connector` changes after launch — keep a switch a verify, never a second path; it hands the new connector to `AppState.activate`, which drops everything the old tenant left: the directory caches, and on a new domain the held previews and the Builder's last result — `tests/test_tenant_switch.py`), `_active_tenant` in `server.py`, `_tenant.html`. The header is tight at 1100 wide: the chip truncates (full text in its `title`) before the nav moves.
- **Touch the route/screen:** `web/routes/setup.py` + its `setup.html` (full page) / `_dwd.html` / `_commands.html` / `_verify.html` templates; keep the import gated through `resolve_dir` so the UI never offers a folder the import would refuse.
