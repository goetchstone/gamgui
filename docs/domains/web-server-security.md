# Domain: Web Server Security

**One line:** The loopback FastAPI app factory and the one middleware that authenticates every request — Host allowlist, per-launch token, cross-origin rejection, and security headers (a script CSP) — plus the template rules that keep Google-supplied directory data from breaking out of HTML attributes and keep every script a same-origin file.

**Owns invariant(s):** #6 (loopback rejects cross-origin — the token cookie is not port-scoped) and #8 (never `| tojson` inside a double-quoted HTML attribute).
**Enforcement home:** `tests/test_server_security.py` (the gate: Host allowlist, bootstrap, cross-origin, token compare, static bypass, the CSP's directives) and `tests/test_template_safety.py` (invariant #8, incl. a durable scanner over all templates; and the inline-script scanner: no `<script>` body, `on*=` handler, `hx-on`, `js:`/`javascript:` or `hx-trigger` filter in any template or rendered screen, every `data-action` handled). No drift guard beyond these two suites.

## Files
- `gamgui/web/server.py` — the app factory (`create_app`), `AppState`, `TokenGateMiddleware`, `TEMPLATES`, `/` and `/healthz`.
- `gamgui/app.py` — picks a random `127.0.0.1` port (`_free_loopback_port`) *before* `create_app(state, allowed_hosts=loopback_hosts(port))`, runs uvicorn in `_BackgroundServer`, builds the `http://127.0.0.1:<port>/?token=<token>` URL, points WKWebView at it. Without pywebview, `_serve_in_browser` prints `BROWSER_MODE_WARNING` then the URL (developer fallback); a frozen `.app` refuses it (`SystemExit`).
- `gamgui/web/templates/base.html` — the shell; loads the same-origin vendored htmx (configured by a `<meta name="htmx-config">`: `allowEval` and `allowScriptTags` off), the prebuilt `/static/app.css` (Tailwind compiled at build time, `make css` — see build-packaging) + external Google Fonts (the only cross-origin fetch; guarded by `Referrer-Policy: no-referrer`), then `/static/app.js` and the page's `{% block scripts %}`.
- `gamgui/web/static/app.js` — every page's behaviour: one delegated `click` listener runs the `data-action` of the clicked control (`copy`, `hint`, `print-sheet`, `clear`, `scroll-to`; its arguments in other `data-*`), a delegated `input` listener for typed confirms (`data-unlocks`/`data-expect`), `[data-tabs]` tab bars, and the busy indicators. `window.GamGUI.actions` is the registry a page script adds to. Page scripts, each loaded only by its page: `builder.js` (Run kept in reach, the type-ahead pickers, the result filter + pager, the row-actions menu; the domain comes from `#builder-root`'s `data-domain`), `groups.js` (the Groups board: the finder's `aria-current` and the add field's combobox, reading `data-group`/`data-val`), `onboarding.js` (`data-reveals`, `ob-edit`, `ob-add`), `signatures.js` (the scope lists, `sig-load`).
- `gamgui/web/templates/_board_members.html`, `groups.html`, `_calendar*.html`, `_suspend*.html`, … — carry directory data; use the `data-*` + `el.dataset` pattern and single-quoted `hx-vals` (see #8).

## How it works
`AppState.create()` mints `token = secrets.token_urlsafe(24)` per launch. `create_app(state, *, allowed_hosts)` adds `TokenGateMiddleware` (given that token and the exact Host set), mounts `/static`, and includes one router per screen. `allowed_hosts` is required — `loopback_hosts(port)` = `{127.0.0.1:<port>, localhost:<port>}` in the real app, `tests/helpers.py` `TEST_HOSTS` (`testserver`, TestClient's default) in route tests; a bare string raises `TypeError`. Every request hits `TokenGateMiddleware.dispatch`: first the Host check (anything not in `allowed_hosts`, case-insensitive, → 403 — even `/healthz`), then `_same_origin` (reject cross-origin with 403), then the `/static` (`== "/static"` or `startswith("/static/")`) + `/healthz` bypass, then `_token_ok` against the cookie, then against `?token=` (which sets an httponly, SameSite=strict, session-scoped cookie). `_secure` stamps `SECURITY_HEADERS` on **every** response, including the 403s. `_lifespan` cancels in-flight `asyncio` jobs on shutdown.

## Invariants & the failure history
- **#6 — origin check comes *before* the token check, on purpose.** Cookies are not port-scoped (RFC 6265 §8.5), so `SameSite=Strict` treats every other port on `127.0.0.1` as the same site and would attach our cookie to a form POST fired by any other local process — a "simple request", no preflight. `_same_origin` blocks that: `Sec-Fetch-Site` in `{cross-site, same-site}` → reject (`same-site` *is* the other-loopback-port case); else compare the `Origin` header to `scheme://host` (host, because the port is runtime-chosen). Missing `Origin` is allowed (native WKWebView / curl / TestClient send none). Introduced in `f090d04` ("loopback CSRF").
- **Host allowlist comes first, before even `/healthz`.** A DNS-rebound page (`evil.example` → `127.0.0.1`) is same-origin *with itself*, so `_same_origin` passes it; only `Host` (`evil.example:<port>`) gives it away, and without the check `/healthz` answered it — a port oracle for our random port. The port is part of the match (Starlette's `TrustedHostMiddleware` strips it, which is why it isn't used). Until 2026-09-23 any Host was accepted.
- **The static bypass is a path *segment* match.** `startswith("/static")` would have exempted a future `/staticfoo` or `/static-export` route from the token. A percent-encoded `/static/%2e%2e/users` still only reaches the `StaticFiles` mount (404) — routing never normalizes dot segments — and is tested.
- **Token compare is constant-time and byte-based** (`secrets.compare_digest` on UTF-8 bytes). `compare_digest`'s *str* form raises `TypeError` above U+007F, and starlette decodes raw header bytes as latin-1, so a garbled non-ASCII cookie/query must return **403, not 500** — regression-tested. Timing-safe compare landed in `f2b4a3d`.
- **Session cookie only.** The token rotates every launch, so no `Max-Age`/`Expires` — persisting it just widens the theft window.
- **Browser mode leaks the cookie by design; it is a developer fallback (decision D2).** A cookie set by `127.0.0.1:<port>` is sent to *every* `127.0.0.1` port, so a page on another local server the browser visits receives the token and can drive GamGUI with curl (no Origin → allowed). The Origin and Host checks cannot stop that. The native window's WKWebView has its own cookie store, separate from the operator's browser, so the cookie only reaches another port if that window itself is navigated there; the packaged `.app` bundles pywebview and refuses the fallback. If browser mode ever matters for real use, the fix is to serve it on a random `<rand>.localhost` host (host-only cookie) — the alternative in plan item S2, not taken.
- **#8 — directory data never uses `| tojson` in a double-quoted attribute.** `tojson` does not escape `"` (it targets `<script>` and single-quoted attrs). Attacker-influenced group/member text (from Google) goes into an autoescaped `data-email="{{ m.email }}"` and JS reads `el.dataset.email`; where JSON is needed it lives in **single-quoted** `hx-vals='{...}'`. Landed with the loopback-CSRF fix (`f090d04`): the group-members drag board (`_board_members.html`/`groups.html`) had passed `m.email` into JS via `tojson`. The board has no drag or `hx-vals` any more (plan U7): a member's address rides in an autoescaped hidden `<input value>`, a group in `data-group` and a suggested person in `data-val` (`tests/test_template_safety.py` renders each with a hostile value).
- **CSP `script-src 'self'` (plan Q13, 2026-09-24): no inline script runs.** `TokenGateMiddleware.CSP` is `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' https: data:; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'`. Until then it had no `script-src` because the templates carried inline `<script>` blocks and `on*=` handlers; they all moved to `static/*.js` (above), so a template XSS — markup smuggled in by directory data — renders inert. Each loosening has a reason: `style-src 'unsafe-inline'` because signature HTML is inline-styled (email HTML has to be) and its preview is a sandboxed `srcdoc` iframe, which **inherits this policy**; the progress bars' `style="width: N%"`, `base.html`'s `<style>`, htmx's indicator `<style>` and the credentials-sheet print frame need it too. `img-src https:` for signature logos on remote hosts (the `img-src` clamp was declined, see the plan). The Google Fonts pair in `style-src`/`font-src` keeps the brand type; vendoring the fonts would let both drop to `'self'`. No `'unsafe-eval'`: htmx's `allowEval` is off, so an `hx-on`, a `js:` in `hx-vals`, or an `hx-trigger` filter (`click[ctrlKey]`) would not run — the scanner rejects them. Verified in headless Chrome (12 screens and the key flows, below). `Referrer-Policy: no-referrer` stops the `?token=` in the first URL leaking to `fonts.googleapis` via `Referer`.

## Gotchas / mock-lies traps
- This domain is almost entirely HTTP/CSRF/XSS logic; the mock GAM (`tests/fixtures/mock_gam.sh`) and the vendored grammar (`gamgui/resources/gam7/GamCommands.txt`) do **not** exercise it — the guard is a real browser's request behavior, which `TestClient` only approximates. `Sec-Fetch-*` header semantics and cookie port-scoping are browser facts; TestClient sends whatever you tell it, so tests must set those headers explicitly (they do).
- Any *new* template that needs to hand a Google-supplied value to JS must use the `data-*`/`dataset` pattern — the `test_no_tojson_inside_a_double_quoted_attribute` scanner catches the tojson mistake but not, e.g., building an attribute by string concatenation.
- `Origin: null` (sandboxed iframe / `file://`) is treated as cross-origin and rejected — verified in the parametrized test.
- `/static/app.css` is served through the same token-exempt `/static` bypass as htmx; it is generated, so a template that adds a Tailwind class needs `make css` (the in-browser compiler used to style whatever the DOM carried; build-packaging's gotcha has the rule).
- Not every directory-data XSS here is an invariant-#8 case. `signatures.html`'s scope dropdown had a *separate* DOM-XSS (`f2b4a3d`): JS built `<option>` markup by `innerHTML` string-concat of Google OU/dept/location values. The fix was `createElement` + `value`/`textContent`; since Q13 the options are server-rendered (Jinja-escaped) inside one `<template data-scope>` per scope, which `signatures.js` clones — never a JS string. JS that renders directory values must still avoid `innerHTML` concat, which no scanner catches (the CSP stops a script running, not markup being injected).
- **A partial's `<script>` never runs.** htmx's `allowScriptTags` is off and the CSP forbids inline script, so behaviour for a swapped-in partial lives in a static file that is already on the page, reached by delegation (`document.addEventListener`, `data-action`) or an `htmx:afterSwap` listener — never a `<script>` in the partial. A page's own file goes in its `{% block scripts %}`.
- A Tailwind class written in a static JS file (e.g. the tab bar's `border-brand-blue`) is found by `make css` — `tailwind.config.js` scans non-vendor `static/**/*.js`.

## Testing / live-verification status
`tests/test_server_security.py` drives the middleware end-to-end via `TestClient` against the real `loopback_hosts(8765)` rule (cross-origin GET/POST/export rejected, same-origin + no-Origin allowed, non-ASCII token → 403, headers on the 403, a foreign/portless/other-port Host → 403 on every path incl. `/healthz`, both loopback spellings accepted, `/staticfoo` needs the token). `tests/test_app_window.py` covers the browser-mode warning and the frozen refusal. `tests/test_template_safety.py` renders hostile values through the real Jinja env and statically scans every `*.html` for unsafe `| tojson` placement and for inline script (plus every main screen's rendered HTML). All run fully offline. The CSP itself is a browser fact TestClient can't exercise: Q13 was checked once in headless Chrome over the DevTools protocol (mock-backed app, `--use-mock-keychain`, 1100×760) — the 12 main screens, user-detail tabs by keyboard, the current-signature iframe and Copy HTML, a suspend preview → confirm, onboarding's account creation → credentials sheet Copy and Print, role Edit and the group picker, the signature scope lists → preview iframe → typed count → polled Apply → template Load, the groups drag board, the Builder's hint chips, type-ahead, preview → run, result filter/pager and row menu, a calendar delete → Cancel, and an offboarding preview → run → polled job: zero CSP violations or JS errors, while a control injected `<script>` and `onerror=` were blocked and reported. WKWebView was not driven; the pywebview print path is unexercised. **No real-tenant verification is needed or meaningful here** — this layer never touches GAM; it is exercised purely by the HTTP + template tests. The only live-ish concern is that WKWebView/real-browser header behavior matches the TestClient assumptions, which is not automatically re-checked.

## To do common tasks here
- **Add/patch an auth or header rule:** edit `TokenGateMiddleware` (`_same_origin`, `_token_ok`, `SECURITY_HEADERS`, `CROSS_ORIGIN_FETCH_SITES`) in `gamgui/web/server.py`, then extend `tests/test_server_security.py`. Keep the Host → origin → token ordering.
- **Build an app in a new test or script:** `create_app(state, allowed_hosts=TEST_HOSTS)` under `TestClient`; `create_app(state, allowed_hosts=loopback_hosts(port))` for anything served by uvicorn on a real port — never a wildcard.
- **Add a new screen/route:** add `gamgui/web/routes/<name>.py`, import + `app.include_router` it in `create_app`; it inherits the gate automatically — no per-route auth.
- **Render Google/GAM directory data in a template:** put the value in a `data-*` attribute (autoescaped) and read `el.dataset.*` in JS; if you need JSON in an attribute use single-quoted `hx-vals='...'`, never a double-quoted attr. Add a case to `tests/test_template_safety.py`.
- **Give a control behaviour:** `data-action="<name>"` (+ its arguments as `data-*`) on the element, and the handler in `app.js`'s `actions` (shared) or as `GamGUI.actions["<name>"]` in the page's static file; for non-click events, a delegated listener keyed on a `data-*` attribute. Never an `on*=` attribute or an inline `<script>` — the CSP blocks both, so the button would silently do nothing (`test_no_template_carries_an_inline_script_handler_or_eval` and `test_every_data_action_has_a_handler` fail first).
- **Add state shared across requests:** add a field to `AppState` (defaults via `field(default_factory=...)`); it is reachable as `request.app.state.gamgui`.
